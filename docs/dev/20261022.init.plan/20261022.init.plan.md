## 1. 项目定位与核心哲学

本项目由 `tiny-c-interpreter` 演进而来，定位为**纯 TypeScript 手搓实现的算法竞赛级 C++ 运行时与教学级状态机工具**。

- **应用场景**：面向代码竞赛（洛谷、Codeforces 基础题/普及组）常见模式代码；
- **理论哲学**：
  > “编译和解释没有绝对的界限，他们的界限是模糊的。”  
  > “程序不过是一个状态机：`S₀ ──(action)──> S₁ ──(action)──> ···`” —— 致敬南京大学 蒋炎岩 (jyy) 老师
- **多端交付**：一套纯净的核心状态机引擎，驱动 Koishi 机器人插件（聊天交互评测）与 Web 可视化调试器（GitHub Pages）。

## 2. 为什么选择纯手搓（拒绝 Fork 与 Wasm）

| 方案 | 评价 | 决策 |
| :--- | :--- | :--- |
| **Fork JSCPP** | 2015 年陈旧 CommonJS/ES5，PEG.js 扩展现代 C++ 极易语法冲突，无快照调试基因 | ❌ 仅作为设计思想参考 |
| **Clang/TCC Wasm** | 过于厚重（数十 MB），黑盒运行，失去纯 TS AST 级别可观测性与时间旅行能力 | ❌ 放弃 |
| **纯 TS 从头手搓** | 严格模式类型安全、递归下降可控性高、原生支持执行快照与状态机回溯 | ✅ **核心方案** |

## 4. 语言与语法边界策略 (Contest Subset)

不做完整 ISO C++ 规范，专注算法竞赛常见写法，采用“降维打击”策略：

### 4.1 预处理宏清洗层 (Preprocessor)
- 词法前置拦截 `#include`，静默忽略 `<bits/stdc++.h>`、`<iostream>`、`<vector>` 等；
- 过滤 `using namespace std;` 与 `cin.tie(0)` / `ios::sync_with_stdio(0)`；
- 简单单行宏替换：处理 `#define int long long`、`#define rep(...)` 等；
- 兼容选手写出的 `long long main()` 与 `signed main()` 函数声明。

### 4.2 内存与数据模型
- 采用**高级对象引用模型**（标量存 TS 原生类型，引用 `&x` 内部采用 `{ get, set }` 槽位）；
- 杜绝底层裸内存物理地址黑洞，保证调试面板变量展示直观清晰。

### 4.3 宿主内置 STL 策略 (Host Built-in Objects)
- 不做深渊般的 C++ 模板元编译；
- `std::vector`、`std::string`、`std::pair`、`std::sort` 直接通过 TS 原生数据结构与算法包装，兼具性能与可观测性。

## 5. 交互与多模式设计

### 5.1 三种工作模式
1. **纯编译批量运行 (Batch Run)**：全量 AST 语法与类型校验通过后，一次性全速运行（Koishi 默认）；
2. **解释执行模式 (Live REPL)**：边走边解释，逐语句产生副作用并动态增长状态；
3. **步进调试模式 (Interactive Stepper)**：带状态机游标、断点与时间旅行回溯（WebUI 默认）。

### 5.2 Koishi 插件：三段式渐进交互 (`session.prompt`)
用户发送 `cjudge` / `crun` 触发多轮引导：
- **Prompt 1/3 (代码)**：输入 C++ 代码（自动清洗 ```cpp 反引号，支持“取消”随时退出）；
- **Prompt 2/3 (输入)**：输入 stdin 数据（支持 `-` 跳过）；
- **Prompt 3/3 (判题/运行切换)**：输入期望输出自动比对判题（返回 AC / WA / TLE / CE），输入 `-` 进入纯运行打印。

### 5.3 WebUI 调试器：四键天王与时间旅行 (Time-Travel)
- **四键控制**：`⏮ 上一行` (Line Prev)、`⏭ 下一行` (Line Next)、`⏪ 上一步` (Step Prev)、`⏩ 下一步` (Step Next)；
- **回溯机制**：运行时维护 `history: VMStepSnapshot[]` 快照栈，点上一行/上一步时直接出栈回滚，变量面板与标准输出瞬间倒流。

### 5.4 📊 jyy 状态机图模型 (jyy State Machine Mode)
- **状态节点 (Node)**：$\langle \text{PC}, \text{Scope Variables} \rangle$，例如 `S2_L11_[a:20,b:22]`；
- **转移边 (Edge)**：标注引发状态变化的语句或微步动作（如 `cin >> a <- 20`）；
- **动态防爆保护**：坚决不做静态 $M \times N$ 状态爆炸；仅记录实际执行可达轨迹（Reachable Trace），超出阈值采用滑动窗口截断，防止浏览器卡死；
- **全模式联动**：
  - 编译模式：跑完展示全景轨迹图 + 进度滑块回放；
  - 解释模式：动态生长图；
  - 调试模式：游标与高亮呼吸灯随单步与时间倒流实时跃迁。

### 5.5 📚 预设教学与演示案例集 (5 Preset Examples)
核心设计 5 套内置代码、标准输入与预期输出（作为共享常量定义在 `core` 中，供 WebUI 与 Koishi 的 `cexample` 复用）：

## 6. 同步机制：`sync_plugin.py` 规范

- **脚本路径**：`scripts/sync_plugin.py`，采用 Python 编写，适配 `uv run`；
- **参数约束**：仅接收 `--dst-path` 传入目标 Koishi 项目的根目录；
- **内联打包**：自动将 `packages/core/src` 源码完整内联至目标插件的 `src/core/` 目录中，使目标插件完全自包含，在宿主中运行 `yarn && yarn dev` 即可秒级加载。
